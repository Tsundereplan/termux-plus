Chapter 1
Meet Termux Plus

Termux Plus is a personal customization build of Termux — the popular Android terminal emulator and Linux environment. It is not a fork that drifts away from the official app: instead, the repository stores only a small set of modified files (an overlay) on top of the real termux/termux-app source, and a GitHub Actions workflow clones upstream at a pinned commit, applies the overlay, and compiles the APK on GitHub's servers. Every push produces a fresh, installable build in the Releases tab.

Why does this matter to you? Because you get real upstream Termux — same engine, same packages, same bootstrap — with the styling and quality-of-life upgrades layered on top. When upstream fixes a bug, the build can pick it up by moving one pinned commit reference (see Chapter 9).

Chapter 2
Getting the APK

Every push to the repository triggers a build. The finished APKs appear in two places: as per-ABI artifacts on the latest Actions run, and on the Releases page under the continuous tag ("Termux Plus — Continuous Build"). The release is rebuilt on every push, so the newest build always replaces the old one.

Important — read before installing Termux Plus keeps the package name com.termux (the bootstrap binaries hardcode it — see Chapter 3), but it is signed with a different key than the official app. Android will refuse to install it over the official Termux. You must uninstall the official Termux app — and the official plugin apps (Termux:API, Boot, Float, Widget, Styling) — first. These builds are debug-signed and meant for personal use.

Keep your files: back up before uninstalling

$ # run this INSIDE your old Termux, before uninstalling: tar -zcf /sdcard/termux-backup.tar.gz -C /data/data/com.termux/files ./home

This packs your entire home directory (scripts, configs, projects) into a single archive on shared storage, which survives the uninstall. After Termux Plus is installed and bootstrapped, restore it with:

$ tar -xzf /sdcard/termux-backup.tar.gz -C /data/data/com.termux/files/home

A note on F-Droid vs GitHub builds: the official Termux on F-Droid is signed by F-Droid's key, and the GitHub release of official Termux by its authors — neither matches this build's key, so switching from either source still requires the uninstall step above. You only go through it once; from then on, newer Termux Plus builds install directly over older ones because the signing key stays the same.

Chapter 3
Bootstrap, explained

When you open a freshly installed Termux Plus for the first time, you will see a brief "installing bootstrap" phase before the prompt appears. Here is what actually happens. Android does not let apps ship a full Linux system inside the APK, so the APK only contains a tiny downloader. On first launch it fetches a bootstrap: a compressed mini root filesystem — a starter OS containing the apt package manager, coreutils, bash and just enough infrastructure to bootstrap itself.

That system is unpacked into the app's private storage under a fixed path called $PREFIX:

$ echo $PREFIX /data/data/com.termux/files/usr # everything you install lives inside this tree: # binaries, libs, /etc, apt lists ... the whole "distro"

Two practical consequences follow. First, every prebuilt Termux package assumes that exact path — which is why Termux Plus must keep the package name com.termux: the private storage path is derived from the package name, and changing it would break every compiled binary in every package. This is also why the uninstall-first rule from Chapter 2 exists (same name, different signature).

Second, "customizing the bootstrap" in the literal sense would mean rebuilding thousands of packages. The practical approach — the one Termux Plus takes — is to keep the official bootstrap mechanism untouched and layer a post-install package set on top: the setup wizard in Chapter 4 installs the essentials kit, themes, fonts and desktop packages right after bootstrap. Same effect, none of the maintenance burden.

Tip The first pkg update after bootstrap downloads fresh package lists and can take a minute on slow mirrors. If downloads fail, run termux-change-repo and switch mirrors — this fixes the vast majority of "package not found" errors.
Chapter 4
One-time setup

After installing the APK and letting bootstrap finish, clone the repository and run the interactive wizard:

$ pkg install -y git $ git clone https://github.com/Tsundereplan/termux-plus.git $ cd termux-plus $ bash setup/install-termux-plus.sh

The script is conservative by design: it asks before every optional step, and it never deletes an existing configuration without saving a backup first (your old ~/.zshrc becomes ~/.zshrc.termux-plus-backup, for example). The six steps:

1
Essentials bootstrap
Installs the daily-driver kit: git curl wget zip unzip nano openssh termux-api proot-distro zsh. Skippable — you can install these manually later.
2
Termux Plus commands
Copies ttheme, tfont and start-desktop into $PREFIX/bin so they work from anywhere.
3
Color schemes
Installs all 12 schemes into ~/.termux/termux-plus/themes/ and applies Tokyo Night — unless you already have a colors.properties, which is kept untouched.
4
Nerd Font
Downloads MesloLGS Nerd Font (the font Powerlevel10k recommends) and installs it as ~/.termux/font.ttf. An existing custom font is kept.
5
Prompt upgrade
Installs Zsh + Oh My Zsh + Powerlevel10k, sets the theme in ~/.zshrc (with backup), and optionally makes Zsh the default shell.
6
XFCE desktop
Enables the x11 repository, installs XFCE4 and the termux-x11 launcher package, and checks whether the Termux:X11 companion app is present (Chapter 8).

At the end the script runs termux-reload-settings so the new theme and font apply without a reboot. Restart the app once for everything to settle, and you are done — the rest of this guide is about using what you just installed.

Chapter 5
Themes, your way

Termux Plus gives you three interchangeable ways to control the terminal's colors, all sharing the same state — switch from the app, then confirm from the CLI, or vice versa. Nothing is locked in, and nothing requires a rebuild.

Way 1 — the in-app picker

Open Settings → Termux → Termux Plus → Terminal color scheme. You get a radio list of every bundled scheme; picking one applies it immediately through the same reload mechanism the external Termux:Styling app uses. The Reset to default entry removes the custom colors and returns to the built-in scheme. (That external Styling app keeps working too, by the way — same colors.properties contract.)

Way 2 — the ttheme command

ttheme
interactive picker with live truecolor swatches
ttheme <name>
apply a scheme instantly, e.g. ttheme dracula
ttheme -l
list all installed schemes
ttheme -c
show the current scheme
ttheme -r
remove colors.properties → built-in default colors

Way 3 — your own colors.properties

Schemes are plain text files in ~/.termux/termux-plus/themes/. Drop any .properties file in there and it appears in both pickers automatically. The format is a flat list of hex colors:

# ~/.termux/termux-plus/themes/my-theme.properties # termux-plus-theme: my-theme <- name marker (used by ttheme -c) background=#1a1b26 foreground=#c0caf5 cursor=#c0caf5 color0=#15161e # black color1=#f7768e # red # ... color2 through color15: the classic 16 ANSI slots. # 8=bold-black, 9=bold-red, etc.

The active scheme is written to ~/.termux/colors.properties — that file is the single source of truth Termux itself reads. If you edit it by hand, run termux-reload-settings (or just reopen the app) to apply it.

Chapter 6
Fonts

A terminal lives on its glyphs, and Termux Plus ships its font workflow around Nerd Fonts — popular monospace fonts patched with thousands of extra icons: folder and file-type icons for ls plugins, Git branch symbols, powerline arrows that Powerlevel10k uses to draw its segments. Without a Nerd Font those symbols render as boxes; with one, your prompt and tooling turn into a proper dashboard.

The tfont command handles everything. It downloads straight from the official ryanoasis/nerd-fonts releases, so fonts are always current:

tfont
interactive picker
tfont <name>
install & apply, e.g. tfont jetbrains-mono
tfont <file.ttf>
install any .ttf you have on disk
tfont -l
list the catalog
tfont -r
remove font.ttf → Termux built-in font

The six curated families:

NameCharacter
mesloMesloLGS NF — the Powerlevel10k recommendation, installed by the setup wizard
jetbrains-monoCrisp, tall x-height, made for code — this guide's own typeface
cascadia-codeMicrosoft's terminal font, friendly curves with coding ligatures
fira-codeThe ligature classic: != and -> become single glyphs
hackNeutral and highly legible at small sizes
roboto-monoAndroid's own mono — feels native on a phone

Whatever you install lands in ~/.termux/font.ttf, which is the single font slot Termux reads. Applying is automatic — tfont calls termux-reload-settings for you.

Chapter 7
The prompt

The stock prompt — a shy ~$ — tells you almost nothing. Termux Plus replaces it with a two-layer upgrade. Oh My Zsh is a configuration framework for the Z shell: it brings sensible defaults, hundreds of optional plugins (Git aliases, completions, the works) and an easy theme system. Powerlevel10k is the theme that sits on top: a fast, informative prompt that shows your directory, Git branch and status, command duration and exit codes — rendered as colored segments with powerline arrows.

Because Termux's background is a solid color, P10k's segment colors are exactly where the "gradient look" comes from: layered blues, greens and magentas building a prompt that reads like a status bar.

The first time you start Zsh, the P10k configuration wizard launches automatically. It asks a handful of questions — diamond and arrow glyphs (testing whether your Nerd Font renders), prompt style (lean, classic, rainbow, pure), character set, icons, spacing — and then writes a matched ~/.p10k.zsh. Answer honestly and you get a prompt that fits your font and taste precisely.

$ # re-run the wizard anytime to restyle the prompt: $ p10k configure
Tip If the wizard's diamond and lock icons show as boxes, your active font is not a Nerd Font — run tfont meslo and restart the app before configuring. Your previous ~/.zshrc is saved as ~/.zshrc.termux-plus-backup if you ever want to go back.
Chapter 8
XFCE desktop

Termux can run complete graphical desktops, and Termux Plus makes it a one-command affair. The piece most people miss is that it takes two components: the X11 packages inside Termux (installed by the setup wizard) and the Termux:X11 companion Android app, which acts as the actual screen. The companion app is Wayland-based under the hood and bridges X11 clients into an Android window.

If the wizard did not find the companion app during setup, install it from F-Droid or GitHub releases — one-time, ~10 MB. Then from any Termux Plus session:

$ start-desktop

The script starts the display bridge in the background, waits for it to come up, then launches the XFCE session with DISPLAY=:0 so every desktop application draws into the Termux:X11 window. Switch to that app and your desktop is there; from XFCE's terminal you can install more GUI software the usual way, e.g. pkg install firefox. To leave, log out of the XFCE session or stop the bridge from Termux.

Tips Audio inside the desktop needs PulseAudio: pkg install pulseaudio && pulseaudio --start --exit-idle-time=-1. And if you ever crave KDE or GNOME: they are not packaged for native Termux, but a proot-distro Debian running KDE/GNOME displayed through Termux:X11 is the established route — the same start-desktop pattern generalizes to it.
Chapter 9
Updating

Two kinds of updates exist, and both are one-step. Getting a newer Termux Plus build is simply installing the new APK over the old one — same signing key, same data: your files, themes and configurations survive untouched. Watch the continuous release, or any tag you build later.

Moving to a newer upstream Termux is controlled by a single pinned commit in the workflow file:

# .github/workflows/build-apk.yml env: TERMUX_APP_REF: 8629e632fcb95da272221be327db653fb24befe9

Either edit that SHA to a newer termux-app commit and push, or run the workflow manually: Actions → Build Termux Plus APK → Run workflow, and type any upstream branch, tag or SHA into the termux_app_ref input. The build then applies the overlay on top of that ref — a minute later there is a fresh APK with your customizations riding on the new upstream code.

Chapter 10
Troubleshooting
SymptomFix
Installer says "App not installed"The official Termux (or a plugin app) is still present. Uninstall all of them first — back up with the Chapter 2 command.
Theme or font changes do nothingRun termux-reload-settings, or fully close and reopen the app. Check that the file is ~/.termux/colors.properties / ~/.termux/font.ttf.
Icons / prompt glyphs are boxesNot a Nerd Font. Run tfont meslo (or any catalog font), restart, then p10k configure.
pkg errors, packages not foundRun termux-change-repo and pick a different mirror, then pkg update. Usually network/mirror flakiness.
Powerlevel10k wizard never appearedStart it manually with p10k configure. Make sure Zsh is running (echo $ZSH_THEME).
start-desktop says the companion app is missingInstall the Termux:X11 Android app (F-Droid or GitHub releases), then run start-desktop again.
Desktop is black / apps do not drawThe display bridge needs a moment; if it persists, re-run start-desktop so it restarts the bridge cleanly. Keep Termux sessions alive in the background.
Custom theme does not show in the pickersThe file must be .properties inside ~/.termux/termux-plus/themes/ with a # termux-plus-theme: marker line as its first line.

Still stuck? Every command from this guide also lives inside the commented scripts in the setup/ directory of the repository — short and safe to read, which is exactly the point of keeping Termux Plus an open overlay rather than a magic binary.
